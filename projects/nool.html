Personal project

Nool

Personal project · Machine learning, forecasting, full-stack app

The Problem

Nool started with my grandfather's shop in Tamil Nadu. Like a lot of small shopkeepers, he tracked stock mostly from memory: what's selling, what's running low, and which suppliers actually deliver on time. When an item ran out, there was no easy way to know whether ordering it today meant it would be back on the shelf in two days or two weeks.

The Process

  • Demand forecasting: a machine learning model learns each product's sales pattern and predicts what the shop will need.
  • Inventory tracking: the app keeps a live picture of stock and flags what should be reordered before it runs out.
  • Supplier reliability: Nool tracks how each supplier has actually performed, so the shopkeeper knows who to trust and how long a restock will really take.
  • Restock estimates: combining demand and supplier history, it answers the question shopkeepers really care about: if I order now, when will it be back in stock?

The Outcome

Nool taught me that good engineering starts with the person who's going to use it. A forecast is only useful if a busy shopkeeper can read it at a glance, and that lesson about designing for real users carries into the hardware I build now.
